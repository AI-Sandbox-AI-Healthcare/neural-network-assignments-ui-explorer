🏥 The Problem

Identify patients with chronic pain from their EHR. Chronic pain affects roughly 20% of adults but is often under-detected until crisis — early identification enables proactive care and cuts long-term costs.

This is a binary classification task: pain = 1 or pain = 0 per patient.

📊 The Dataset

A curated subset inspired by Synthea, an open-source synthetic EHR generator (no HIPAA concerns). Real Synthea spans dozens of tables across full patient lifetimes; here we extracted 320 patients — small enough to keep the focus on pipeline mechanics.

Why synthetic? Real EHR data requires institutional access. Synthea mimics real population statistics so the skills you build transfer directly to production clinical data.

🔬 The Approach

Build a logistic regression classifier from scratch using only NumPy — no scikit-learn. You implement every equation: gradient descent, log-loss, stratified split, and AUC.

Logistic regression is the clinical gold-standard baseline — fast, interpretable, the benchmark every more complex model is measured against. The sandbox shows your target; pipeline.py must reproduce it.

Class imbalance: A model that always predicts “pain=0” gets 60% accuracy for free — yet it’s completely useless. That’s why we use AUC and F1 instead of raw accuracy.

Keyword Tester
Why does this exist? The dataset has no pre-built label column. We create binary_label by scanning condition_text for 31 pain-related keywords using regex. This is Stage 1 of your pipeline: flag_keyword_match(). The approach generalises — swap the keyword list for any clinical concept and the same code creates a new label.
Patient Table — All Columns

binary_label is the first column, id is second. Scroll right to see all 23 columns. The 19 features used for training are highlighted in blue headers.

Why only 19 features? The 23 columns include 4 that cannot or should not be used as model inputs:
• id — patient identifier, not a clinical signal
• binary_label — the target variable itself (using it as a feature is circular)
• condition_text — label leakage: the label was created from this text, so feeding it back in would let the model read the answer key
• race — demographic attribute excluded to prevent the model from encoding a protected characteristic
